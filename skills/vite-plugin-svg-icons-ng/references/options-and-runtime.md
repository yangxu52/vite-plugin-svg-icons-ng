# Options and runtime choices

Sources: `<Documentation site>/guide/options`, `<Documentation site>/guide/virtual-module`, `<Documentation site>/guide/ssr`, and `<Documentation site>/guide/typescript`.

## Public options

Use the docs definitions when explaining these `createSvgIconsPlugin` options:

- `iconDirs: string[]` (required): SVG directories; relative paths use Vite `root`.
- `symbolId: string` (default `icon-[dir]-[name]`): must contain `[name]`; `[dir]` is the relative directory portion. The expanded ID must start with a letter and contain only ASCII letters, digits, underscores, and hyphens.
- `inject: 'body-first' | 'body-last'` (default `body-last`): insertion position for plugin-managed HTML.
- `htmlMode: 'script' | 'inline' | 'none'` (default `inline`): automatic sprite generation strategy.
- `customDomId: string` (default `__svg__icons__dom__`): root injected SVG ID.
- `strokeOverride: boolean | string` (default `false`): override stroke with `currentColor` or a chosen color.
- `failOnError: boolean` (default `false`): warn and skip an error SVG, invalid `symbolId`, or duplicate `symbolId` when false; fail compilation when true.
- `bakerOptions: BakerOptions` (default `{}`): advanced pass-through options, including SVGO configuration. If the behavior is not understood, do not override it; prefer changing the source SVG.

`inject` chooses `body-first` or `body-last` placement for the sprite or mounting script generated by the plugin-managed HTML flow. It does not affect manual SSR injection through `virtual:svg-icons/sprite`.

## Automatic HTML and virtual modules

- `htmlMode: 'inline'`: inject the complete sprite during HTML transformation; this is the default.
- `htmlMode: 'script'`: inject a runtime script that mounts the sprite and supports development updates.
- `htmlMode: 'none'`: disable automatic HTML generation.
- `virtual:svg-icons/register`: optional client-side sprite mounting; the documentation recommends `htmlMode: 'none'` when using it.
- `virtual:svg-icons/ids`: import the current generated symbol IDs for selectors or dynamic rendering.
- `virtual:svg-icons/sprite`: import the complete sprite string for SSR or manually assembled HTML.

## SSR choice

- Standard Vite CSR: choose `inline` or `script`; manual injection is not needed.
- A self-managed SSR server: import `virtual:svg-icons/sprite` in the server entry and inject it into the template.
- Framework SSR: use the framework's server HTML hook/template flow to inject the sprite.

In SSR development, if the SSR layer aggressively caches complete HTML or templates, invalidate that cache after icon changes so the next render reads the latest sprite.

## TypeScript

Either add `"vite-plugin-svg-icons-ng/client"` to `compilerOptions.types`, or reference it from an environment declaration file:

```ts
/// <reference types="vite-plugin-svg-icons-ng/client" />
```
